## 1. 模块概述

### 1.1 在系统组合中的位置

M4 是「管皮肤」的入口：设置页新增「皮肤」分组（M6 重组后的第四分组），承载当前皮肤状态、皮肤卡片列表、导入导出与制作器入口。上游消费 M1 全部接口；「应用」动作**写入草稿缓存**（M1 DraftStore，含该侧 skinId 与叠加参数），经底部「预览 · 示例」确认后由操作条「保存」提交设置域 `focusBubbleSkinId / focusUserBubbleSkinId`（决策 4.4 / 总规划 #10）；缩略图与预览消费 M2 组件。

## 2. 皮肤分组结构（设置页第四分组）

```text
▾ 皮肤
  ├─ 助手当前皮肤： [缩略图] 名称 · 类型        [更换▾] [清除]
  ├─ 用户当前皮肤： [缩略图] 名称 · 类型        [更换▾] [清除]
  ├─ [导入皮肤(.dshskin)] [新建皮肤] [导出全部] [恢复内置皮肤]
  └─ 卡片网格（每卡片）：
       [悬停播放缩略图]
       名称 · 类型徽标(九宫格/动图/序列帧) · 侧别徽标 · 内置徽标(builtin)
       [应用到助手] [应用到用户] [编辑副本] [导出] [删除]
```

- 「更换▾」= 打开本列表的快捷选择（滚动定位）；「清除」= 草稿中该侧 skinId 置 ''（保存后回到普通背景层，bgImage 等字段自动恢复生效，L1-#8 让位语义）；首次对任一侧动作时若尚无草稿，以已保存值为基底克隆生成（决策 4.4）；
- **应用即写草稿（决策 4.4 / 总规划 #10）**：卡片「应用到助手/用户」「清除」只更新页面草稿（工作副本即时生效，draft.json 经 M1 DraftStore 去抖持久化）并驱动底部「预览 · 示例」实时渲染，**不直接写设置域**；仅预览区操作条「保存」提交（含 skinId 在内的全部草稿字段），「放弃更改」连同皮肤选择一并回滚；当前皮肤两行按**草稿值**渲染并带未保存圆点；
- 应用时若 manifest 带 textColorHint/overlayHint 且当前草稿对应字段为空 → toast 提示「该皮肤建议文字色 #xxx，是否应用？」（一键写入草稿——可预览、可随「放弃更改」回滚，不强制）。

## 3. 导入 / 导出

- **导入**：按钮 + 拖拽投递区；两条路径（决策 #9 分工）：
  - **落库导入**（默认）：选 .dshskin → M1 校验 → 直接入库出卡片（不打开编辑器）；
  - **进编辑器导入**：裸素材文件（PNG/GIF/APNG/WebP/多选 PNG）→ 进入 M3 工作台预填参数后保存（「打开皮肤包」按钮在 M3 工作台内，编辑已有分享包走那条路）；
- **导出**：单卡片导出 .dshskin（浏览器下载）；「导出全部」= 每皮肤一个包依次下载（不打包合集，v1 简化）；
- 导入的包重新生成 skinId（M1 §2），同名共存不冲突；
- **内置皮肤**（M1 §7）：卡片带「内置」徽标；工具行提供「恢复内置皮肤」按钮（重新注册被删除的内置包，幂等）。

## 4. 状态与反馈

| 状态 | 呈现 |
|------|------|
| OPFS 不可用 | 分组顶部横幅「当前浏览器不支持皮肤库，其余功能不受影响；一键换外观已切换为传统预设」；列表/按钮禁用，半透明/背景图功能不受影响；两侧气泡编辑弹窗自动回退显示原 6 套预设下拉作为一键换外观降级（决策 #14，此时恢复 focusBubblePreset/focusUserBubblePreset 字段读写） |
| 皮肤损坏（damaged） | 卡片置灰标「已损坏」，仅 [删除] 可用 |
| 库为空 | 空状态引导卡：「新建皮肤」+「导入 .dshskin」两按钮 + 一句说明 |
| 删除确认 | 二次确认弹层（宿主 Modal）；若正被某一侧使用，确认文案追加「该皮肤正被助手/用户气泡使用，删除后恢复默认背景」 |
| 导入校验失败 | 行内错误列具体缺项（M1 §5 语义透传） |

## 5. 失败场景（原则4）

| 场景 | 行为 |
|------|------|
| 删除被使用皮肤 | M4 删除成功后由 watchSkins 联动置 ''：**已保存值与草稿值分别检查置空**——草稿引用被删皮肤时同步清空该侧草稿 skinId（避免「保存」写出悬空 id），已保存残留 id 照旧归位（决策 4.4 草稿化后的补充） |
| 导出时皮肤资产缺失 | 该卡片导出按钮禁用 + tooltip「资产缺失无法导出」 |
| 导入重复取消（文件选择器取消） | 无操作无报错 |
