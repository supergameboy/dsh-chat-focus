## L5 根因分析（五问法）

1. **为什么看不到 subagent 界面？** ui-subagent 的目录组件 SubagentHeaderLineage 从未注册到任何插槽。
2. **为什么没注册？** 它通过 `slots.inject('conversation.session.header.lineage', …)` 等待该插槽被声明后才注册；而 SlotRegistry.inject 在插槽未声明时静默等待、永不回调（无报错）。
3. **为什么无人声明？** 该子插槽的唯一声明者是宿主 ui-conversation（apply.ts children 表 + ConversationSession 面包屑渲染点）。cordis.patch.yml 将 ui-conversation 禁用并以 dsh-chat-focus 整体替换（shadowing 占用 `conversation.session.header`）。
4. **为什么 fork 没有这个声明与渲染点？** fork 基于 host rc.5 分叉；"subagent 头部切换器"（lineage 插槽 + 目录 UI）是之后才进入上游的新特性。fork 替换整个会话头部时没有跟进这条新契约——用户升级到 0.1.1-rc.2 宿主后该特性在官方 UI 出现，而在 fork UI 中缺席。
5. **根本原因**：**fork 与宿主的插槽契约演进脱节**。替换式占用 header 插槽意味着继承"自行声明并渲染全部子插槽"的义务，但没有机制提醒新出现的子插槽；ui-slots 只对"注册进未声明插槽"报错，对"注入等待方永远等不到"完全静默。

### 触发条件

- 宿主 ≥ 引入 lineage 插槽的版本（dsh-v0.1.1-rc.x），且加载 dsh-chat-focus（禁用 ui-conversation）
- 任何后台 subagent 启动后：目录按钮不渲染 → 无法从 GUI 打开/查看任何子代理会话 → "丢失 subagent 状态"
