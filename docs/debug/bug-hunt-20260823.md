## L5 根因分析（五问法）

1. **为什么看不到 subagent 界面？** ui-subagent 的目录组件 SubagentHeaderLineage 从未注册到任何插槽。
2. **为什么没注册？** 它通过 `slots.inject('conversation.session.header.lineage', …)` 等待该插槽被声明后才注册；而 SlotRegistry.inject 在插槽未声明时静默等待、永不回调（无报错）。
3. **为什么无人声明？** 该子插槽的唯一声明者是宿主 ui-conversation（apply.ts children 表 + ConversationSession 面包屑渲染点）。cordis.patch.yml 将 ui-conversation 禁用并以 dsh-chat-focus 整体替换（shadowing 占用 `conversation.session.header`）。
4. **为什么 fork 没有这个声明与渲染点？** fork 基于 host rc.5 分叉；"subagent 头部切换器"（lineage 插槽 + 目录 UI）是之后才进入上游的新特性。fork 替换整个会话头部时没有跟进这条新契约——用户升级到 0.1.1-rc.2 宿主后该特性在官方 UI 出现，而在 fork UI 中缺席。
5. **根本原因**：**fork 与宿主的插槽契约演进脱节**。替换式占用 header 插槽意味着继承"自行声明并渲染全部子插槽"的义务，但没有机制提醒新出现的子插槽；ui-slots 只对"注册进未声明插槽"报错，对"注入等待方永远等不到"完全静默。

## 追加：折叠框展开导致会话底部空白（2026-09-09 修复）

**现象**：展开「活动」折叠框后，向下滚动会话会出现一段多余空白；展开越多，空白越大。

**定位**（CDP 实测真实 dsh 页面，逐层二分 + 受控实验）：

| 观测 | 数值 |
|------|------|
| 外层滚动器 `[data-conversation-scroll]` 的 `scrollHeight` | 2473 |
| 真实内容高度（`.viewArea` + 吸底 composer） | 1170 |
| 泄漏量 | **1303px** |
| 折叠框内层 `.body` 的自身滚动溢出（`scrollHeight - clientHeight`） | 2032px |
| 给 `.body` 临时加 `contain: paint` 后的 `scrollHeight` | **1170（泄漏归零）** |

**根因**：折叠框 body 同时设置 `overflow-y: auto` 与 `overflow-x: hidden`。Chromium 在这种组合下会把**内层滚动容器的内容折进外层滚动器的 scrollable overflow**，于是外层 `scrollHeight` 凭空多出一段；吸底的 composer 是外层滚动器的最后一个子元素，它的自然位置不随泄漏增长，滚到底部时它就停在内容中段，下方全是空白。

**修复**：`RuntimeFoldBox.module.css` 的 `.body` 增加 `contain: paint`（把内层溢出挡在自身之内，不再参与外层溢出计算）。同时给折叠开关加了锚定：展开/收起后保持摘要行位置；读者本来贴底时重新贴底（含下一帧补正，覆盖行分波挂载）。

**回归验证**：修复后同一状态实测 `scrollHeight = expected = 1170`、`leak = 0`、`composerBottomGapAtFloor = 0`（内层仍有 1776px 滚动溢出）；`typecheck` / `decl` / `bundle` 与三套单测全绿。

## 追加：毛玻璃「无效」（2026-09-10 用户反馈修复）

**现象**：设置毛玻璃（弱/中/强）后看不出任何变化。

**定位**（CDP 实测）：`backdrop-filter` 的计算值一直是正确的（`blur(10px) saturate(1.4)`），但气泡底纹层自身是**不透明**的（主题蓝 / 用户底色 / 背景图）。`backdrop-filter` 模糊的是元素**背后**的内容，随后元素的背景会画在模糊层之上——不透明背景把模糊整个盖住，所以视觉上毫无效果。

**修复**：毛玻璃预设同时把底纹变半透明，模糊才透得出来。

| 预设 | 表面不透明度 |
|------|--------------|
| 弱 4px | 0.72 |
| 中 10px | 0.55 |
| 强 18px | 0.40 |

实现：`ChatBubble` 在检测到毛玻璃预设时发布 `--cf-bubble-glass-alpha`；`.backdrop` 用 `color-mix(... calc(var(--cf-bubble-glass-alpha,1) * 100%), transparent)` 淡化底色；背景图片移到独立的 `.imageLayer` 上按同一系数淡化（这样只有图片变淡，不会连带遮罩）。

**实测证据**：在消息列铺 18px 黑白条纹，把一条助手气泡设为半透明 + blur(10px) 后截图——气泡区域内的条纹被平滑成均匀灰，气泡外的条纹依旧锐利（`docs/screenshots/glass-proof.png`）。同时确认该宿主 DOM 下 `backdrop-filter` 能采样到气泡背后的内容（无 backdrop root 阻断）。

## 追加：fit 语义变更引发的九宫格回归（2026-09-10 用户反馈修复）

**现象**：气泡「变形」、边框「被破坏」、毛玻璃依旧无效。

**根因**：上一轮把 `fit` 从 `cover|stretch` 扩成 `nine|cover|contain|stretch` 时，**旧记录里的 `fit: 'cover'/'stretch'` 被当成了「整层铺放」**——内置皮肤与用户此前保存的皮肤都是九宫格语义，于是 `border-image` 不再生效、素材被拉伸变形、素材自带的边框区随之消失（看起来像"边框被破坏"）。毛玻璃则是被不透明的素材盖住。

**修复**：

| 项 | 处理 |
|----|------|
| 旧记录 | `normalizeRecord` 以 `position` 字段是否存在判定旧版记录：旧版且 kind=image 且切片内缩非零 → `fit` 归一回 `nine`（`position` 与新 fit 语义同批引入，是可靠的版本标记） |
| 内置皮肤 | `builtin-skins` 显式声明 `fit: 'nine'` |
| 毛玻璃 | 玻璃系数同时作用于皮肤图层（`.skinLayer`/`.skinNine`），素材随之半透明，模糊可见 |
| 边框 | 边框改为**独立子层**（`.borderRing`，位于素材之上）：无皮肤与整层皮肤下按圆角显示；九宫格皮肤由素材决定形状，该行在设置页置灰并说明 |

**实测**：真实会话里用户内置皮肤的计算样式恢复为 `border-image-slice: 14 fill`、圆角正常（截图 `docs/screenshots/border-ring.png`）；开启毛玻璃后气泡层 `opacity: 0.55` 且 `backdrop-filter: blur(10px)`，素材半透明、模糊透出。

### 追加修正：动图素材的边框（2026-09-10）

上一轮把边框环逐个分支补写时漏了 **GIF/APNG（animated）与多帧精灵** 两条路径——「改 A 丢 B」的典型。

**结构性修法**：`SkinBackdrop` 改为**单一容器**——只有九宫格（`image + fit=nine`）走 `border-image` 独立分支（边框由素材决定），其余所有族（animated / sprite / video / 非九宫格 image）共用一个容器，内部按类型选图层内容（背景图 / 精灵 / 视频），边框环与圆角裁剪只写一次。这样新增素材族时不可能再漏掉边框环。

覆盖矩阵：无皮肤 ✓ / animated ✓ / sprite 单帧 ✓ / sprite 多帧 ✓ / video ✓ / image 九宫格 → 由素材决定（设置页置灰说明）✓ / style 纯参数 ✓（走无皮肤路径）。

### 追加修正：九宫格切片复用背景图裁剪代码（2026-09-10 用户要求）

用户要求「图片素材的九宫格拉伸使用裁剪背景图片的剪裁代码」，此前自建的 `NineSliceCropper`（四边手柄）被弃用并删除。

**做法**：`ImageCropper` 恢复为原来的自由裁剪实现（contain 舞台 + 可拖拽框 + 四角手柄 + 九宫格参考线），只增加两个**可选**参数：

| 参数 | 用途 |
|------|------|
| `onRect` | 把裁剪框（相对 0..1）实时上报给调用方 |
| `showActions` | 隐藏「取消/确定」按钮行（制作器内联编辑用） |

制作器「切片与几何」的静态图分支现在直接渲染这个组件：裁剪框即九宫格的**可拉伸中段**，其四边即切片内缩（`sliceFromRect` 换算），右侧实时预览同步；「按内容自动估算」与内边距跟随切片按钮保留。同时修掉草稿默认 `fit: 'cover'` 导致静态图不走九宫格的问题（现按素材类型默认 `nine`/`cover`）。

**实测**：制作器几何步渲染出 `stage + frame + 四角手柄 + 4 条参考线`（即背景图裁剪组件本体），自动估算与背景适配（含九宫格档）同时可见。
